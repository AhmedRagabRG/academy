# Data Model: Ticket Management

**Feature**: 011-ticket-management | **Date**: 2026-08-09

## Common Rules

- IDs are branded opaque strings and never user-editable.
- Mutable aggregate roots carry `version`, `createdAt`, `updatedAt`, `createdBy`, and `updatedBy`.
- Dates are ISO instants; organizational calendar boundaries use the acting context's timezone.
- All records carry `organizationId`; branch-scoped records may also carry `branchId`.
- Service projections are clones. Activity records have no update/delete path.

| organizationId | OrganizationId | Required scope boundary |

| statusId | WorkflowStatusId | Required; active seeded statuses or archived state |
| lastActiveStatusId | WorkflowStatusId | Preserved while archived for restore |
| priorityId | PriorityId | Required; service-provided configuration |
| departmentId | DepartmentId | Required, active on create/update |
| branchId | BranchId? | Optional related operational branch |
| teamId | TeamId? | Optional assignment |
| employeeId | EmployeeId? | Optional assignment; must belong to team when both set |
| customerId | CustomerId? | Optional related customer |
| studentId | StudentId? | Optional; at most one |
| conversationId | ConversationId? | Optional; at most one |
| dueAt | instant? | Optional; past dates allowed but shown overdue |
| tagIds | TagId[] | Unique IDs; configured tags only |
| commentCount | non-negative integer | Derived from non-deleted comments |
| attachmentCount | non-negative integer | Derived from active attachments |
| version | positive integer | Incremented once per successful ticket-changing command |
| completedAt | instant? | Set on entering Done; cleared when leaving Done |
| archivedAt / archivedBy | instant/user? | Both present only when archived |
| createdAt / createdBy | instant/UserId | Immutable creation audit |
| updatedAt / updatedBy | instant/UserId | Latest successful command |

### Ticket invariants

- A ticket may have neither assignment, team only, employee only, or both.
- When both are set, the employee must be an active member of the team.
- Archived tickets do not appear in active board reads.
- Restore uses `lastActiveStatusId`; if unavailable, Backlog is the seeded fallback.
- Delete is an administrative mock-session removal and requires explicit confirmation.
- Related entities are contextual references, not owned aggregates.

## WorkflowStatus

| Field | Type | Rules |
|---|---|---|
| id | WorkflowStatusId | Stable configured ID |
| code | string | Seeded: backlog, todo, in-progress, waiting, review, done, archived |
| label | localized text | Arabic required |
| category | active / archived | Archived excluded from board |
| order | integer | Logical workflow and board order |
| colorToken | token name | Shared semantic token, not raw color |
| isDefault | boolean | Exactly one active default |
| isActive | boolean | Historical values remain resolvable |

### Seeded active transitions

Every active status may change to another active status when the actor holds `tickets.change.status`. Archive and restore are separate commands requiring their own permissions. Entering Done sets `completedAt`; leaving Done clears it. Every actual transition increments version and appends `status-changed` activity.

## Priority

Configured record with `id`, `code`, localized label, order, semantic token, and active flag. Seeded values are Low, Medium, High, and Critical. Changing it requires `tickets.change.priority` and creates `priority-changed` activity.

## TicketAssignment and AssignmentHistory

Current assignment is stored on Ticket. Each change appends an immutable activity payload containing previous/new team and employee IDs plus display snapshots. No-op assignments do not increment version or append history.

## TicketComment

| Field | Type | Rules |
|---|---|---|
| id | CommentId | Unique |
| ticketId | TicketId | Required parent |
| authorId | UserId | Acting user; immutable |
| message | string/rich text | Required, non-empty, bounded |
| isInternal | true | Fixed in this feature |
| createdAt | instant | Immutable |
| updatedAt | instant? | Set on edit |
| deletedAt | instant? | Soft marker used to preserve activity truth |

Only the author with comment permission may edit/delete. Deleted comments do not contribute to card counts and render as a tombstone only where audit context requires it.

## TicketAttachment

Fields: `id`, `ticketId`, `name`, `mediaCategory` (image/PDF/document), `mimeType`, `sizeBytes`, `uploadedBy`, `uploadedAt`, and mock `previewRef`. Schema validates supported categories, configured maximum size, non-empty filename, and pending upload identity. Binary content is not durably stored.

## TicketActivity

| Field | Type | Rules |
|---|---|---|
| id | ActivityId | Unique and stable |
| ticketId | TicketId | Parent aggregate |
| sequence | positive integer | Strictly increasing per ticket |
| type | ActivityType | created, assignment-changed, status-changed, priority-changed, comment-added/edited/deleted, attachment-added, updated, archived, restored, deleted |
| actorId | UserId | Required |
| occurredAt | instant | Required |
| payload | discriminated structured value | Typed previous/new values or referenced entity IDs |

Activity is append-only, chronological by sequence, and written atomically with the successful command it describes.

## Related Summaries

`CustomerSummary`, `StudentSummary`, `ConversationSummary`, `TeamSummary`, `EmployeeSummary`, `DepartmentSummary`, and `BranchSummary` expose only IDs and display-safe fields Ticket Management needs. Historical activity embeds minimal labels so later renames do not rewrite prior meaning.

## PermissionContext

Fields: actor ID, organization ID, current employee ID, team IDs, allowed branch IDs, permission-key set, timezone, and locale. `VisibilityScope` derives as global, team, assigned, or none. `TicketCapabilities` derives booleans/reasons for edit, assignment, status, priority, comment, attachment, archive, restore, and delete but never replaces command authorization.

## TicketListQuery and CursorPage

Query fields: mode (active/archived), optional status IDs, priority IDs, team IDs, employee IDs, department IDs, branch IDs, tag IDs, creator IDs, normalized search, sort, cursor, and page size. Filter groups combine with AND; values inside one group combine with OR. Cursor encodes the stable last sort tuple. Page returns items, next cursor, total matching count, and query fingerprint.

## DashboardSummary

Derived from the same scoped ticket repository and query boundary: open, mine, team, waiting, critical, and completed-today counts. “Open” excludes Done and Archived. “Completed today” uses `completedAt` in organizational timezone.

## SavedView

Fields: `id`, owner ID, name, normalized query without cursor, presentation mode, optional selected status, and timestamps. Saved views contain preferences only—not result IDs or permission scope—and are re-evaluated against the current actor on use.

## State Transition Command Order

For every write: validate actor/permission → resolve ticket in actor scope → validate state/assignment rule → compare `expectedVersion` → validate command schema → apply aggregate change and activity atomically → clone projection → invalidate relevant query families. Unauthorized and failed commands produce no mutation or activity.
